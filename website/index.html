What is KCM

KCM stores knowledge as columnar relation spaces rather than pointer-based graphs. Each attribute of a knowledge fact — subject, predicate, object, confidence, evidence, timestamp, context, version, priority, owner — is stored in its own independent, contiguous, SIMD-aligned column.

Traditional Approach

Pointer -> Pointer -> Pointer -> Value

Random pointer chasing, no SIMD, no column compression

KCM Columnar Approach

Column[Subject]  -> Sequential -> SIMD-ready
Column[Predicate] -> Sequential -> SIMD-ready
Column[Object]    -> Sequential -> SIMD-ready

Sequential memory access, SIMD-parallel filtering, independent compression

Key Features

Columnar Storage

10-column fact store with cache-aligned DenseVec. 64-byte SIMD-aligned contiguous memory with independent per-column compression.

Query Engine

5 algebraic operators with AVX2 SIMD acceleration. Bitmap indexing, zone maps, and bloom filters for fast filtering.

Reasoning Engine

Forward-chaining inference with confidence calculus. Conjunction, disjunction, negation, and weighted combination.

Security

AES-256-GCM encryption, RBAC with 5 permission levels, audit logging, and GDPR compliance.

Compression

Dictionary, Delta, Gorilla, and RLE encoding. Zstd and LZ4 with per-column codec selection.

Transactions

ACID transactions with WAL-based crash recovery. Tombstone-based soft delete with active count tracking.

Interfaces

C FFI (13 functions), Python bindings, REST API (actix-web), gRPC (tonic), KQL parser.

Optimization

Cost-based query planner with filter pushdown, join reordering, statistics-driven selectivity, adaptive execution.

Quick Start

Build

cargo build --release

Insert and Query

let kb = KnowledgeDatabase::new()?;
let fact = Fact::new(
    SubjectID(1), PredicateID(0),
    ObjectID(2), 0.9)?;
kb.insert(&fact)?;

let results = kb.query()
    .with_subject(SubjectID(1))
    .execute()?;

HTTP Server

cargo run --release -p kcm-server
