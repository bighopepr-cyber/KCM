# ADR-004: WAL-Based Crash Recovery

## Status
Accepted

## Context
KCM must survive crashes without data loss. Options include:
- WAL (Write-Ahead Log): Log changes before applying
- ARIES-style: More complex logging with compensation
- Copy-on-write: Maintain multiple versions

## Decision
Use WAL with CRC32 checksums for crash recovery.

## Consequences

### Positive
- Simple implementation
- Fast writes (append-only)
- Deterministic replay
- CRC32 detects corruption

### Negative
- WAL grows unbounded (requires compaction)
- Replay time proportional to WAL size

## Alternatives Considered

| Alternative | Pros | Cons | Decision |
|------------|------|------|----------|
| ARIES | Industry standard | Complex implementation | Rejected |
| CoW | Multi-version | Storage overhead | Rejected |
| **WAL (chosen)** | Simple, fast writes | Requires compaction | **Accepted** |
