# ADR-006: BLAKE3 for Hashing

## Status
Accepted

## Context
KCM needs cryptographic hashing for:
- File integrity verification (checksums)
- Key derivation (encryption keys)
- Audit log chaining (tamper detection)

Options: SHA-256, SHA-3, BLAKE2, BLAKE3

## Decision
Use BLAKE3 for all hashing needs.

## Consequences

### Positive
- Fastest cryptographic hash (parallelizable)
- Variable-length output
- Simple API
- Better than SHA-256 in every metric

### Negative
- Newer than SHA-256 (less battle-tested)
- Not FIPS-compliant (future concern)

## Alternatives Considered

| Alternative | Pros | Cons | Decision |
|------------|------|------|----------|
| SHA-256 | FIPS-compliant, battle-tested | Slow | Rejected |
| SHA-3 | NIST standard | Slow | Rejected |
| BLAKE2 | Fast | Not parallelizable | Rejected |
| **BLAKE3 (chosen)** | Fastest, parallelizable | Newer | **Accepted** |
