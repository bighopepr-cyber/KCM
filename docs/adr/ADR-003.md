# ADR-003: Forward-Chaining Inference

**Document ID:** ADR-003
**Version:** 1.0.0
**Status:** Accepted
**Author:** KCM Engineering Team
**Date:** 2026-08-04
**Deciders:** Architecture Guardian (P5)

## Context
KCM needs to derive new knowledge from existing facts using rules. Options include:
- Forward chaining: Apply rules to known facts to derive new facts
- Backward chaining: Start from goal, work backwards to find supporting facts
- Hybrid: Combine both approaches

## Decision
Use forward-chaining inference with convergence detection.

## Consequences

### Positive
- Deterministic execution order
- All derived facts are eagerly computed
- Simple convergence detection (fixed-point check)
- Easy to track provenance (which rules derived which facts)

### Negative
- May compute unnecessary derivations
- Requires convergence limit (max iterations = 1000)

## Alternatives Considered

| Alternative | Pros | Cons | Decision |
|------------|------|------|----------|
| Backward chaining | Only computes needed facts | Complex, non-deterministic | Rejected |
| Hybrid | Best of both | Complex implementation | Future work |
| **Forward chaining (chosen)** | Simple, deterministic | May over-compute | **Accepted** |
