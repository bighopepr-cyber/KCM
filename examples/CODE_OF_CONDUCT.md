# examples/ Community Guidelines

> For project-wide community guidelines, refer to the [CODE_OF_CONDUCT.md](../CODE_OF_CONDUCT.md) located in the repository root.

## Respect

- Treat all contributors with respect regardless of experience level, background, or identity.
- Respect different perspectives and approaches to solving problems.
- Acknowledge that examples serve users with varying skill levels.
- Be patient with newcomers asking questions about examples.

## Professional Communication

- Use clear, constructive language in code comments, PR descriptions, and issue discussions.
- Avoid dismissive or condescending tone when reviewing example code.
- Provide actionable feedback — suggest specific improvements rather than vague criticism.
- Use issue templates when reporting problems with examples.

## Code Review Etiquette

- Review example code with the understanding that it will be read by learners.
- Suggest improvements that enhance clarity without sacrificing correctness.
- Acknowledge well-written examples and good documentation.
- Focus feedback on:
  - Correctness of KCM API usage
  - Clarity for the target audience
  - Adherence to example coding standards
  - Completeness of documentation

## Collaboration

- Coordinate on which examples to add via issues before starting work.
- Avoid duplicating effort — check existing examples and open issues first.
- Share knowledge about KCM APIs that may be useful for example implementations.
- Help maintain examples across language subdirectories when APIs change.

## Reporting Issues

| Issue Type | Where to Report |
|------------|----------------|
| Bug in example code | GitHub Issue with `examples` label |
| Missing example | GitHub Issue with `enhancement` + `examples` labels |
| Security concern | Private security disclosure (see [SECURITY.md](SECURITY.md)) |
| Documentation error | GitHub Issue with `docs` + `examples` labels |
| Performance issue | GitHub Issue with `performance` + `examples` labels |

## Enforcement

Violations of these community guidelines will be handled through the same process described in the repository-wide [CODE_OF_CONDUCT.md](../CODE_OF_CONDUCT.md). Examples-specific enforcement includes:

- Reverting PRs that introduce harmful or misleading examples.
- Removing examples that violate security policies.
- Blocking contributors who repeatedly submit low-quality examples despite feedback.
